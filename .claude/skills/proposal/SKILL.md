# Proposal

Goal: a short, honest `docs/01-proposal.md` (template already exists; fill it in). This is quick. Aim for one
or two rounds of questions.

1. Read `docs/reference/project-ideas.md` and `docs/reference/deliverables.md` (for the due date).
2. If the student hasn't chosen, ask what they enjoy (games, sports, travel, food, something else?) and
   recommend 1–2 ideas that fit, with one line each on what makes it fun and what makes it tricky.
   Be honest: Arcade (Snake) and Escape Room have tricky state; League/Coffee/Road Trip are data-heavy
   but straightforward.
3. Once chosen, run one grilling round using the rules in `.claude/skills/grill-me/SKILL.md` (read it), focused on:
   - who uses the app and what a 60-second demo of it would show
   - the student's own twist/theme (sport, setting, shop name, Snake vs tic-tac-toe)
   - one stretch goal they'd love if time allows
   - their biggest worry
4. **Dealer's Choice:** the idea must have the same weight as the official five. Check it against the minimum
   bar in `docs/reference/project-ideas.md` (Dealer's Choice section) and fill in the extra Dealer's Choice
   section of the proposal. Remind them to talk with the instructor about the idea; it must be approved before they start building.
5. Write the proposal **in the student's voice, using their words**. Keep their sentences when they're good.
   Restate the official requirements as a checklist in the proposal so later skills can track them.
6. Ask them to read it and change anything that doesn't sound like them.

End: "Proposal ready. Run `/checkpoint` (tag it `proposal` when asked), then `/clear`. Next: `/project-plan`."
